# 08 — 憲法 (予算 / 承認 / killswitch / 認証情報)

**スコープ**：自己拡張・外部作用・自発介入する存在に必要な**安全弁**。予算上限、外部作用前の承認、
緊急停止、そして最高機微の認証情報管理。むしろこれが JARVIS 的な「信頼できる相棒」感の土台。

## 小分けドキュメント計画

- [ ] `constitution.md` — 破ってはいけない不変ルール（何を絶対に自分で決めさせないか）
- [ ] `budget.md` — token/credit/実行回数の上限とtier連動（残予算でtierを下げる）
- [ ] `approval-flow.md` — 書き込み/ネットワーク/権限変更/プロンプト自己書換えの承認。自発介入時の非同期承認
- [ ] `killswitch.md` — 緊急停止（shell実行を止める一点／常駐の停止）
- [ ] `credential-vault.md` — 認証情報の秘匿保管・利用・有効性チェック（最小権限・監査）
- [ ] `self-edit-guards.md` — LLMが編集する対象（閾値D6/プロンプト/allow）の clamp・版管理・ロールバック

## 現時点の知見

- **safeShell が執行点**：外部作用は全て [06-tools](../06-tools/) の `safeShell` を通り、ここで deny/承認/予算が効く。
- **予算はtierと連動**：残予算が細ければ [03-router](../03-router/) が全体を1tier下げる。
- **自己改変にガード**：スキル追加・allow拡張・プロンプト自己書き換えは**承認＋版管理＋ロールバック**の内側でのみ（[07-metacognition](../07-metacognition/)）。
- **認証情報の自己管理は最高機微**：渡された資格情報の保管/利用/有効性チェックは、
  専用の秘匿ストア＋最小権限＋監査で扱う。**外部に送る前は必ず承認**。
  - ⚠ SDK横断の注意：ユーザーのメール等の識別情報を無関係サービスに送らない、という既存原則をRuntime全体に適用。
