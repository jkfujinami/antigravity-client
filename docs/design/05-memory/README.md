## 現時点の知見

### ローリング要約（多重解像度）

音声ログは放置で即トークン破綻するので、**時間で解像度を落とす**：

```
[ 直近15分 ]   生データ(逐語)              高解像度・即参照
[ 15分より前 ] 15分ブロック要約            中解像度
[ さらに古い ] 15分ごとに再要約して圧縮    圧縮を重ねる
   │  毎時の保持トークン上限を設定
   ▼  上限到達で それ以上は圧縮しない(=潰しすぎ防止の床)
[ 毎晩 ]  一日分を夜間バッチで要約 → インデックス化
[ 重要事項 ]  別系統で抜けなく管理(圧縮対象外)
```
- **多重解像度**：新しいほど詳しく古いほど粗く。参照コストと情報量の均衡。
- **毎時トークン上限**：圧縮の到達点を決め、それ以上潰さない下限。
- **夜間要約("睡眠")**：1日分を要約しインデックス追加。
- **重要事項は分離管理**：予定・約束・決定・人物の重要属性は要約に巻き込まず別ストアへ（要約はロスあり）。
- 各層の要約は軽量モデル(T0/T1)で回す（[03-router](../03-router/)）。

### レーン構成（案）

| レーン | 中身 | 圧縮 | 例 |
|---|---|---|---|
| **raw** | 直近15分の逐語 | なし | 生の文字起こし |
| **rolling** | 15分ブロックの多重要約 | あり(再帰) | 「10:15-10:30 …の議論」 |
| **daily index** | 日次要約+索引 | 済 | 「9/6: A社打合せ、締切変更」 |
| **important** | 予定/約束/決定/人物属性 | なし | 「締切 9/20」「B氏=上司」 |
| **knowledge graph** | 人物・物・関係・知識 | 構造化 | (B氏)-[上司]->(マスター) |

各レコードに `ts / speaker? / confidence / source`（[04-perception](../04-perception/) D4 と整合）。
