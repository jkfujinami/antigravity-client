# 10 — 複数端末 / プラットフォーム同期

**スコープ**（横断）：複数の端末にまたがって同じ相棒として生活を補助し、いろんなプラットフォームでも
会話できるようにする。どこを「真実の源」にし、何を同期するかを決める機能。

## 小分けドキュメント計画

- [ ] `topology.md` — 中央(1つの真実の源)＋端末クライアント か、P2P同期か
- [ ] `state-sync.md` — 何を同期するか（記憶/登録簿/予算/進行中タスク）と競合解決
- [ ] `platform-adapters.md` — 各プラットフォーム（Slack/ブラウザ/CLI/モバイル…）への会話アダプタ
- [ ] `credential-portability.md` — 端末をまたぐ認証情報の扱い（[08-governance](../08-governance/) と共有）

## 現時点の知見

- **真実の源を1つに**寄せるのが単純（例：常駐カーネルを1台に置き、他端末は薄いクライアント）。
  完全P2P同期は競合解決が重いので後回し候補。
- **同期対象**：まず [05-memory](../05-memory/)（記憶）と [02-registry](../02-registry/)（登録簿）。予算・進行中タスクは要検討。
- **プラットフォーム会話**：既存の web-poc（本家UIをweb配信）や各種アダプタで入口を増やせる（`src/server/web-poc/`）。
- 認証情報の可搬性は最高機微 → [08-governance](../08-governance/) の credential-vault と一体で設計。
